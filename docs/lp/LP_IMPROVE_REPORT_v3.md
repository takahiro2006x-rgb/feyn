## 判断に迷って自分で決めたこと

1. **LPはテンプレートにせず、静的HTMLのまま「相談の欄だけ」差し替える形にした**。Jinjaなどのテンプレートにすると、ページ内の `{ }` を含むCSS・JSとぶつかる心配があり、ほかの表示や計測を変えたくなかったため。差し替えるのは `<!-- CONTACT:START -->`〜`<!-- CONTACT:END -->` の間だけで、それ以外はファイルのままであることをテストで確認している。
2. **初期値（ファイルの中身）を「準備中」にした**。差し替えに失敗したり、ファイルがそのまま配信されたりしても、無効なアドレスが出ることはない（ボタンが出ないだけ）。
3. **相談先が未設定でも、公開前チェックは失敗にしない（注意だけ）**。相談の窓口なしで生徒向けに先に公開する、という判断もありえるため。必要なら `check_before_deploy.py` の注意を要対応に変えられる。
4. **公開前チェックは、【要確認】に限らず【 】で囲んだ所を全部「未記入」として数える**。規約・ポリシーの下書きでは【事業者名】【公開日】のように「要確認」と書かない空欄が多いため。HTMLのコメントの中（利用者に見えない所）と、表示されない「使った人の声」の中は数えない。
5. **特商法の表記の「このページは雛形です」も「下書きの表記」として数える**。指示は「下書き」だったが、同じ意味の注意書きなので。
6. **LPの差し替え処理を `landing_render.py` に分けた**。アプリ本体（`core.py`）は読み込むだけでDBの準備を始めるので、公開前チェックからはDBに触れない形で同じ処理を使えるようにした。
7. **しくみの画面は、少し低い画面（375×640）で撮った**。本物の画面は縦に長く、3枚並べるとスマホのページが長くなるため。結果・苦手ノートの画面も同じ高さにそろえた（結果の画面は「物理 クリア！」の見出しが見える一番上を撮影）。
8. **先生向けのセクションが見えている間は、スマホの生徒向け固定ボタン（無料で始める）を出さないようにした**。`#teachers` で開いた先生に、生徒向けのボタンがかぶらないように。
9. **ページ全体のスクリーンショットでは、スマホの画面下の固定ボタンを隠して撮った**。ページ全体の画像では、固定ボタンがノートの上に貼りついたように写り、実際の見え方と違うため（実際の375×812の画面では、ファーストビューのボタンが見えている間は隠れていることを確認済み）。
