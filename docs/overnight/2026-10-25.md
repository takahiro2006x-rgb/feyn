### 1. 【重大】Gemini API の規約では、18歳未満が使うアプリに使えない

2026-10-25 に公式の [Gemini API 利用規約](https://ai.google.dev/gemini-api/terms)（2026-04-28 更新版）を確認しました。年齢要件の節に、次の趣旨の条件があります。

- 開発者は18歳以上であること
- **18歳未満の人が使う、または使う可能性の高いサービスの一部として使ってはいけない**（教育目的・保護者の同意などの例外の記載は無し）

Feyn は受験生（中高生）向けなので、このままだと規約違反になる可能性が高いです。あわせて、次の2点も分かりました。

- **無料枠では、送った内容（未成年の会話・写真）が Google の製品改善に使われ、人が読むことがある**
- 有料枠ではそれは無くなるが、年齢の条件は有料・無料を問わない

公開・塾への営業の前に、AIの提供元をどうするか決める必要があります。選択肢は「今夜はやらない」の「Geminiモデル一覧」の項に書きました。**ここは法律の判断を含むので、最終的には規約の原文と、必要なら専門家・Google への問い合わせで確認してください。**

### 2. 使っている予備モデルのうち2つが提供終了扱い

[公式の提供終了ページ](https://ai.google.dev/gemini-api/docs/deprecations)（2026-10-22 更新）によると、**gemini-2.0-flash と gemini-2.0-flash-lite は「最短で2026年6月1日に提供終了」**です。10/25 にモデル情報を問い合わせたところ、4つともまだ取得できたので、今すぐ止まっているわけではありません。

ただし、いつ使えなくなってもおかしくありません。今のコードは、予備への切り替えを「枠切れ（429）」「過負荷（503）」のときだけ行います。2.0系が「存在しない」というエラーを返すようになると、**2番目の 2.0-flash で切り替えが止まり、3番目以降（2.5-flash-lite・Groq）に届かない**おそれがあります。指示どおりコードは変えていません。対応案は下に書きました。

## 「今夜はやらない」項目の実装案

### パスワード再設定のメール認証化
- **案**：再設定用のトークンを発行し、ハッシュで保存する（30分で失効・1回限り）。リンクをメールで送り、開いた先で新しいパスワードを設定する。送信元・宛先ごとの回数制限も付ける。
- **メリット**：秘密の質問（クラスメイトなら答えを知っていることがある）より安全。先生が仮パスワードを発行する手間も減る。
- **デメリット・注意**：今は「友達に試してもらうとき本物のメールを入れるのを怖がられないよう、`@` があれば登録できる」設計にしています。この設計とぶつかります。架空のメールの人は使えないので、秘密の質問か先生による再発行を残す必要があります。
- **必要な外部サービス**：メール送信サービス（Resend・Amazon SES・SendGrid など）と、独自ドメイン（迷惑メールに入らないよう、送信元の認証設定が必要）。
- **費用感**：ドメインが年1,000〜3,000円程度。送信サービスは月数千通程度まで無料枠のあるものが多いです（各社の料金ページで要確認）。

### 返答のストリーミング表示
- **前提の補足**：指示書には「単一の同期ワーカー」とありました。しかし `60e6caa` の時点で、すでに **gthread・1プロセス・8スレッド・タイムアウト120秒**（`gunicorn.conf.py`）に変えてあります。このため、ストリーミング中も他の人のリクエストは止まりません。
- **案**：
  - `/api/chat` にストリーミング版（Server-Sent Events）を追加し、Gemini の stream API で届いた分から画面に出す。数式（KaTeX）は、最後に一括で描画する。
  - `【会話終了】` の判定・DBへの保存・利用状況の記録は、届き終わってから行う。
  - スレッド数は16程度に増やす。1本のストリーミングが数秒〜十数秒スレッドを使うためです。
- **メリット**：体感の待ち時間が大きく減る（最初の文字が1〜2秒で出る）。
- **デメリット**：
  - 途中でモデルが失敗したときの予備への切り替えが難しい。
  - 同時に処理できる数がスレッド数で決まる。
  - Renderの無料プランが休止から起きるときの遅さは変わらない。
- **外部サービス・費用**：不要。

### 納得度バーのAI評価連動

- **案B**：1往復ごとに、評価専用の短い呼び出しをする。AIの使用量が約2倍になる。
- **おすすめ**：案A。印が無い・形が崩れているときは、今の「往復数×25%」に戻す。
- **判断が必要な点**：数字が上下すると、生徒がやる気をなくすおそれがある（例：一度下がったら表示上は下げない、などのルールを決める）。

### 疑似偏差値の名称変更・大学名の削除
