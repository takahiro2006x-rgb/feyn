## やったこと

### 1. 塾・先生向けの入口（最優先）
- 料金のあとに「塾・学校の先生へ」セクションを新設。アプリに実在する機能だけを記載（学習状況・苦手ノート・会話ログ・つまずきマップ・課題・パスワード再発行）。先生用ダッシュボードと生徒詳細の本物の画面を、ブラウザの枠に入れて表示。
- 「導入について相談する」ボタン（mailto）。アドレスは `landing.html` の `id="contactBtn"` の1か所だけ。今は `contact@example.com`（ダミー）。
- ヘッダーに「先生の方へ」、フッターの「塾・学校の先生へ」とよくある質問の先生向け項目を、このセクションへ向けた。

### 2. 本物のアプリ画面
- `scripts/lp_shots.py app` で、使い捨てのSQLiteにデモ生徒（デモ生徒A〜D）・デモ先生を作り、AIの返事は台本で置き換えて、実際の画面を操作して撮影。
- 画像は WebP（スマホ画面は幅520px、先生の画面は幅1120px＝表示サイズの約2倍）で `static/lp/` に保存。5枚で合計約170KB。
- しくみの1枚目（作った会話画面）と、結果の見本（作った答案）を本物の画面に置き換え。しくみの2・3枚目の会話の絵は、入力方法や会話の終わり方を見せる役なので残した。
- 本番では動かない: `RENDER` か `DATABASE_URL` があると即終了（テストあり）。

### 3. コンセプトの統一
- Feynは「あなたが教える相手の生徒役（鋭く質問してくる）」に統一。「ライバル受験生」「あなたが先生として」「赤ペンで」の言い方をなくした（テストで確認）。
- ノートの赤い書き込みは「Feynからの質問」と読めるよう、ノートの上に凡例「赤字＝Feynからの質問」を付け、書き込みも質問の形に。
- 「ほんとに？」は見出しの1回だけ。リード文は2文に。スマホのファーストビューを詰め、ノートの絵の上部（質問2つ分）が1画面目に入るように（ノートの上端 586px → 453px）。

### 4. 信頼の材料
- 数字の帯（7科目・5区分・3種類・30日後）を「何ができるか」に書き換え（質問で返してくる／苦手ノートに残る／忘れかけたころ聞き直しに来る／7科目）。

### 5. 表現を控えめに

## 判断に迷って自分で決めたこと

1. **先生の画面はPCの幅で撮った**（指示はスマホ幅）。先生のダッシュボードと生徒詳細は、スマホの幅だと横にはみ出す作り（375pxの画面で459px）で、LPに載せると「崩れたアプリ」に見えるため。LPではブラウザの枠に入れた。生徒の画面3枚はスマホ幅。
2. **ダッシュボードの画像では、運営向けの「Gemini使用量」と空の「最近提出された課題」を隠した**。どちらも先生に見せたい内容ではないため。画面そのものは本物で、データはデモ用（画像の下に注記あり）。
3. **アプリ本体の肩書き「〇〇担当のライバル」（`script.js`）は変えていない**。今回はLPが対象のため。撮影した会話画面にはこの肩書きは写っていない。LPと合わせるなら、アプリ側も「〇〇を教わる生徒役」などにそろえるのがよい。
4. **先生向けの文で「担当の生徒」と書かなかった**。下の「見つかった問題」1のとおり、今は先生が全生徒を見られるため。
5. **料金のスマホ表示は、11/3に入れた横スワイプをやめた**（今回の指示どおり）。PCも含めてカード形式にそろえた。
6. **受験生プランの目立たせ方は「おすすめ」ではなく「たくさん使いたい人に」**。最初の申し込みは無料プランへの誘導なので、有料を勧める言い方は避けた。
7. **ファーストビューの小さな箇条（7科目に対応・問いで返す・スマホでも）を外した**。帯の内容と重なり、スマホでノートを上げるため。
8. **OGP画像はWebPではなくPNG**。SNSによってはWebPを表示しないため。
9. **規約・ポリシーは .md の下書きを元にページを作る形**にした。中身を直すのは .md、反映は `py scripts/build_legal_pages.py`（ページと下書きが食い違うとテストで気づける）。
10. 指示の「main」は、このリポジトリでは `master`。master には触れていない。

## 追加したテーブル・API

**新しいテーブルはなし**。既存の `events` テーブル（利用状況の記録）に、記録の種類を3つ足した。

| event_type | いつ | mode に入るもの |
|---|---|---|
| `lp_view` | LPが表示された（ログイン中の人は数えない） | なし |
| `lp_cta_click` | 「無料で始める」が押された | ボタンの場所: `header`・`hero`・`board`（中盤の黒板）・`price`・`final`（最後）・`sticky`（スマホの固定ボタン） |
| `lp_contact_click` | 先生向け「導入について相談する」が押された | なし |

- **`POST /api/lp-event`**（ログイン不要）: `{"type": "view"}`・`{"type": "cta", "place": "hero"}`・`{"type": "contact"}` を受け取り、いつも 204 を返す。
  - `user_id`・IPアドレスなど、人を特定する情報は保存しない（ログイン中でも user_id は入れない）。
  - 決まった形以外（知らない種類・知らない場所）は記録しない。
  - 1つのIPから10分に30件まで（数はメモリ上で数えるだけで保存しない）。
- **集計**: `core.compute_lp_metrics(days=30)` が、表示回数・ボタンごとのクリック数・クリック率・相談ボタンのクリック数を返す。
  ```
  py -c "import core; print(core.compute_lp_metrics())"
  ```
  本番のDBで見るときは、Supabase の SQL エディタで:
  ```sql
  SELECT event_type, mode, COUNT(*) FROM events
  WHERE event_type LIKE 'lp_%' AND created_at >= NOW() - INTERVAL '30 days'
  GROUP BY event_type, mode ORDER BY event_type, mode;
  ```
- プライバシーポリシーの下書き「1. 取得する情報」に「紹介ページの閲覧」の行を追記済み。
